# Connect Marketing LP v3

本番を保護する独立Astroプロジェクト。リポジトリルートの既存トップ・CNAME・公開ファイルは変更しません。

## 開発

Node.js 22.23.4以上（検証・CIは24）、npmを使用します。

```sh
cd lp-v3
npm ci
npm run dev
npm run check
npm run build
npm run preview
```

Astroのsiteは `https://connect-mkt.jp`、baseは `/`、静的出力は `lp-v3/dist/` です。ルートの旧index.htmlと新LPのエントリーは独立しています。GitHub Pagesの設定・配信対象を変更しない限り、本番には反映されません。

ビルド後に `scripts/preserve-legacy.mjs` が既存の `en/`、`assets/`、`mcp.json` を出力先にコピーします。旧ファイルは互換性のため保持しており、新事業への継承やAPIの稼働を保証するものではありません。CNAMEはコピー・変更しません。

## 公開前の確認

- フォーム送信サービス、個人情報の取り扱い方針、返信・通知先を決定し、実送信を検証する。
- フォームは現在fieldsetごと無効化。送信・保存を行わず、未実装を画面に明示。
- 実績は `src/data/projects.ts` に追加する。完成かつ掲載許諾済みの項目のみ描画する。顧客案件と自主制作デモの区分を明記する。
- プレビュー用の `noindex,nofollow` を公開承認後に見直す。canonicalとOG URLは本番ルートを指定済み。
- 正式なOG画像、個人情報方針、公開可能なプロフィール詳細を確認する。
- 旧英語ページ・配布ページ・MCP宣言の方針を決定し、互換性とリンクを検証する。
- Pages配信方式の移行は別作業。本ブランチのCIは検査・ビルドのみで、Pages書込権限・OIDC権限・デプロイ処理を持たない。

今回、本番公開・mainへのマージ・DNS・Pages設定変更は行いません。

## レビュー②の表示管理

- 公開可能実績0件では `#works` セクション全体を生成しません。現時点で実績ナビリンクはありません。将来リンクを追加する場合も `publishedProjects.length > 0` と連動させてください。
- 実績は `completed` と `approvedForPublication` の両方が必要です。自主制作も完成・公開可能性を確認してから追加してください。
- 代表名と「これまでの経験」「現在の実務対応」「AIの活用」は `src/data/profile.ts` で編集します。年数、企業名、数値は確認済み情報だけ追記します。
- モバイル固定CTAは問い合わせセクションが画面に入り始めると非表示にし、フォームからフッターまで表示しません。JavaScript無効時も固定CTAは非表示で、ヘッダー・FVの相談リンクが利用できます。

## 問い合わせ：Tally接続の準備（未着手・未確定）

現在のフォームは無効化を維持し、Tallyの読み込み・外部送信・通知を行いません。Tallyは第一候補であり、サービス決定までは接続しません。

決定が必要な事項：

| 設定事項 | 現状・確認内容 |
| --- | --- |
| サービス・管理者 | Tally第一候補。契約、所有アカウント、権限、引継ぎ先を確定 |
| 正式フォームID | 未確定。既存サイトのIDは流用しない |
| 入力項目 | お名前、メール、相談カテゴリー、相談内容、同意は必須。会社名・屋号は任意 |
| 通知・返信 | 通知先メール、送信者名、自動返信、対応担当・返信目安を確定 |
| 個人情報方針 | 利用目的、保管期間、削除窓口、外部サービス利用・保存場所等を確認し、正式ポリシーURLと同意文を決定 |
| 不正送信対策 | Tallyで利用可能なスパム対策・必要な制限を確認 |
| 埋め込み方法 | インライン埋め込みを優先検討。高さ調整、読み込み失敗時の正式フォームURLへの導線を設計 |
| 完了・失敗 | 送信完了表示、二重送信、通信失敗、通知不達時の対応を定義 |

接続手順（別途正式に接続が決まってから実施）：

1. 所有者・通知先・方針を確定し、Tallyで本番用フォームを作成する。必須・任意とカテゴリーを本LPに合わせる。
2. 個人情報方針を掲載し、同意文からリンクする。埋め込み時のデータ取扱いを確認する。
3. 通知先と必要な自動返信を設定し、正式フォームID・公開URLを確認する。秘密情報やAPIトークンはソースに保存しない。
4. 現在の無効フォームを正式な埋め込みへ置換する。ダミーHTMLのdisabledを外すだけの変更はしない。
5. テスト用データで必須検証、同意、送信成功・失敗、通知先到達、返信、迷惑送信対策、二重送信を確認。320pxを含むスマートフォンとキーボード操作で確認する。
6. 確認完了後に限り「準備中」表示を更新する。実際に送信できる状態と画面説明を一致させる。
