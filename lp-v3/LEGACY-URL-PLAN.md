## 決定すべき点

- enを上記暫定案内へ改訂するか、利用実態が明確な場合だけ期限付き維持とするか。旧訴求を無条件に残す案は推奨しない。
- 配布物の権利・内容確認担当と、既存リンクの把握方法。
- MCPの運用責任者・実サーバー・認証・接続先・利用者の有無。宣言だけを残して稼働中と説明しない。

## 実装上の注意

現状 `lp-v3/scripts/preserve-legacy.mjs` はen・assets・mcp.jsonをそのままdistへコピーする。したがって「新LPからリンクしていない」だけでは旧訴求の公開継続を防げない。承認された移行方針を配信成果物側にも反映し、コピー処理と成果物検査を変更する必要がある。

GitHub Pagesは静的配信。任意の301/410レスポンスやサーバー側のRewriteは自由に設定できない。HTMLでの案内・meta refreshはHTTP 301と同じではなく、JSONを読むクライアントの代替にもならない。実際の配信方式に合わせて終了・移動を設計する。
